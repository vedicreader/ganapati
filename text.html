Where a verse ends

Sanskrit sources rarely put one verse on one line. A GRETIL file runs verses together and closes each with a citation, a recitation text glues the verse number onto the last line, and a plain edition may have nothing but daṇḍas. verse_spans cuts a text into verses and returns each one as (start, end, text, citation), where start and end are character offsets into the input and citation is the verse’s id, or None.

It looks for one kind of marker at a time, and uses the first kind that occurs anywhere in the text:

  1. a citation such as // Mn_1.1 //, which becomes the verse’s id;
  2. a Devanagari verse number such as ॥ १॥, which becomes the id;
  3. a double daṇḍa, || or // at the end of a line, which gives no id.

A text with none of these but with numbers at the start of its lines is cut at each number, and the number becomes the id. In the other cases a markdown heading also starts a new verse. A line that begins with > holds a gloss or a translation, and it stays with the verse before it.

def verse_spans(

)->fastcore.foundation.L:

Split text into verses, returning (start, end, text, citation) for each.

The examples below split two verses of the Īśa Upaniṣad by their citations, and a numbered text with no daṇḍas by its line numbers. They also check cite_parts from ganapati.sanskrit.

from ganapati.text import cite_parts, verse_spans
assert cite_parts('BrhUp_1,1.2') == ('BrhUp', ['1','1','2'])
assert cite_parts('Mn_1.1') == ('Mn', ['1','1'])
assert cite_parts('IsUp_4[57M]') == ('IsUp', ['4'])      # the alternate-edition number is dropped
assert cite_parts('not a citation') == ('not a citation', [])

two = ('īśā vāsyam idaṃ sarvaṃ | tena tyaktena bhuñjīthāḥ || IsUp_1 ||\n'
       'kurvann eveha karmāṇi | evaṃ tvayi nānyatheto || IsUp_2 ||\n')
sp = verse_spans(two)
assert len(sp) == 2
assert [c for *_, c in sp] == ['IsUp_1', 'IsUp_2']
assert sp[0][2].startswith('īśā') and sp[0][2].endswith('||')

numbered = ('0nārāyaṇaṃ namaskṛtya\n'
            '  1\n'
            'lomaharṣaṇaputra ugraśravāḥ\n'
            '2samāsīnān abhyagacchat')
sp = verse_spans(numbered)
assert len(sp) == 3
assert [s for *_, s, _ in sp] == [
    'nārāyaṇaṃ namaskṛtya', 'lomaharṣaṇaputra ugraśravāḥ', 'samāsīnān abhyagacchat']

Laying out a verse

A pāda is a quarter of a verse. A printed verse usually shows two pādas on each line, a single daṇḍa (।) after the first half, and a double daṇḍa with the verse number after the second: ॥ १ ॥. Recitation sources often send the whole verse as one line, with a speaker tag such as धृतराष्ट्र उवाच (“Dhṛtarāṣṭra said”) glued to the front and the number in ASCII digits. These functions put such a verse back into the printed shape.

padas cuts one verse at each single daṇḍa, so each output line is a half-verse in the usual case. It puts a speaker tag on a line of its own and closes the last line with ॥ n ॥ in Devanagari digits. Pass num to set the number, or leave it out to keep the number the verse already carries. When you have a whole saṃhitā or chapter in one string, call split_mantras first: it cuts the text at each ॥ n ॥ and returns (number, body) pairs that you can pass to padas one at a time. A single daṇḍa before a number does not count as a marker, because the paryāya hymns of the Atharvaveda print a running count that way. deva_num writes a number in Devanagari digits, and is_word tells a word from a daṇḍa, a verse number or a stray punctuation mark.

The examples below use Gītā 1.1 as the DharmicData corpus prints it, a verse of the Kumārasambhava, the opening of the Yajurveda, and edge cases from the Atharvaveda, the Chāndogya Upaniṣad and the Gītā.

Chunkers

A search index stores a text as chunks, and the chunk boundaries decide what a search result looks like: a chunk that ends mid-verse returns half a verse. chunk_verses cuts on the verse boundaries that verse_spans finds. It joins short verses until a chunk reaches target characters, and splits a verse longer than max_chars at its daṇḍas, never inside a clause. A heading always starts a new chunk. A chunk normally ends as soon as it holds a verse with a citation, so that each cited verse is its own result; pass pack_cited=True to let cited verses share a chunk up to target.

VerseChunker and ProseChunker wrap chunk_verses in the interface of a chonkie chunker, so you can pass either to litesearch’s add_doc(chunker=...). Each chunk carries start_index and end_index, its offsets in the source. VerseChunker aims for 300 characters and allows 900. ProseChunker is for prose such as commentaries, bhāṣyas and the prose Upaniṣads: it aims for 700, allows 1400, and packs cited units together. litesearch reads the chunker’s settings too, and packs text across pages only for a chunker that packs cited units, which the last two checks below confirm.

cs = VerseChunker().chunk(two)

long = ' | '.join(['padam yatra tatra sarvatra gacchati'] * 80) + ' ||'

# because a reader that emits one verse per page is already the right size
assert pack_target(VerseChunker()) == 0
assert pack_target(ProseChunker()) == 700

Reading source files

Sanskrit texts are published in several file formats, and ganapati reads five. Each reader takes a path or the file’s contents as a string and returns (pages, meta). pages is a list of (index, text) pairs, usually one per verse or section, and meta is a dict with the format, the title and whatever else the file states. When you don’t know the format, call sanskrit_parse: it looks at the extension and the first 4,000 characters and calls the right reader.

reader source
gretil_parse GRETIL plain-text editions, the *_u.htm files
tei_parse TEI XML, as GRETIL and SARIT publish it
vr_xml_parse vedicreader <lyrics> XML, which carries audio timings and a word-by-word analysis
vr_json_parse vedicreader content JSON, which carries the same information
dcs_parse CoNLL-U files from the Digital Corpus of Sanskrit (DCS), which give each word’s lemma

is_sanskrit answers a simpler question: whether a piece of text looks like Sanskrit at all, judged by its script, its IAST diacritics, or its citations and daṇḍas.

The vedicreader formats need a few more words. A line marked ignore="true" is printed but not recited, such as a title or a rubric, so the reader leaves it out of the text; the first line of the title section becomes meta['title']. A line aligned to a recording carries start_time_ms, end_time_ms and alignment_id. time_marker writes these into the text as [t 0-1800 a1] so that they survive chunking, and line_times reads them back from a chunk as AttrDict(text, start, end, aid, ms). A line’s translation is written on a following line that starts with >, and its word-by-word analysis on lines that start with > etym:, which line_etyms returns. The metre code ignores > lines and anything in square brackets, so neither a gloss nor a timing is scanned as verse.

VR = """<lyrics>
  <category>vedic</category><tags>rudram</tags>
  <section name="title">
    <line ignore="true">॥ श्रीरुद्रचमकप्रश्नः ॥</line>
  </section>
  <section name="anuvaka 1" meaning="A dual invocation of Agni and Viṣṇu.">
    <line start_time_ms="0" end_time_ms="1800" alignment_id="a1" caption="of one accord"
          etymology="अग्नाविष्णू, agni-viṣṇu, vocative case, dual number, O Agni and Viṣṇu.&#10;सजोषसा, sajoṣas, instrumental case, singular number, of one accord.">अग्नाविष्णू सजोषसेमा<w start_time_ms="0" end_time_ms="900">अग्नाविष्णू</w><w start_time_ms="900" end_time_ms="1800">सजोषसेमा</w></line>
    <line start_time_ms="1800" end_time_ms="3400" alignment_id="a2">वर्धन्तु वां गिरः ॥</line>
  </section>
</lyrics>"""

pages, meta = vr_xml_parse(VR)
assert meta['title'] == '॥ श्रीरुद्रचमकप्रश्नः ॥'        # kept as the title
assert not any('श्रीरुद्रचमकप्रश्नः' in t for _, t in pages)   # and dropped from the content

ts = line_times(pages[-1][1])
assert [t.start for t in ts] == [0, 1800] and [t.ms for t in ts] == [1800, 1600]
assert ts[0].aid == 'a1' and ts[0].text == 'अग्नाविष्णू सजोषसेमा'   # `<w>` children stay out of the line
# the corpus writes a whole word-by-word analysis into one attribute, so every physical line needs the
# `> etym:` prefix: an unprefixed continuation line reaches the scansion as if it were a pāda
es = line_etyms(pages[-1][1])
assert len(es) == 2 and es[0].startswith('अग्नाविष्णू,') and es[1].startswith('सजोषसा,')
quoted = lambda pg: all(ln.startswith(('>', '##')) or '[t ' in ln for ln in pg.splitlines() if ln.strip())
assert quoted(pages[-1][1])
